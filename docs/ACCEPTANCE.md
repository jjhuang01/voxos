## 2. 声纹阈值标定（这不是拍脑袋的数字）

**语料**：macOS `say` 合成 6 个真实音色 × 4 句（Tingting 中文女声作主人；
Meijia 中文女声、Samantha / Karen / Moira 英文女声、Daniel 英文男声作冒充者）。
每音色前 2 句录入、后 2 句测试。**异人试验 60 次，其中含同性别中文女声（最难的冒充样本）。**

| 阈值 | FRR | FAR | 说明 |
| ---: | ---: | ---: | :--- |
| 0.70 | 0% | 13.33% | 太松，8 次里放过 1 次冒名 |
| **0.75（当前出厂值）** | **0%** | **1.67%** | 真麦克风的分界点；合成语料上 FAR 不达标，见下 |
| 0.76 | 0% | 1.67% | 合成语料上仍不满足 FAR < 1% |
| 0.80 | 0% | 0% | 合成语料可用；真麦克风上会开始误拒本人 |
| 0.82 | 0% | 0% | 合成语料的最优点（同人 0.8487 / 异人 0.7816 的中点） |
| 0.84 | 0% | 0% | 可用，但同人侧余量只剩 0.009 |
| 0.86 | 8.33% | 0% | 开始误拒本人 |
| 0.90 | 50% | 0% | 一半的本人语音被拒 |

**决策：出厂值 **0.75**，而不是本语料上看起来最优的 0.82。**

0.82 在**合成语料**上完美（FRR 0 / FAR 0），但在**真麦克风**上是灾难：只录 1 句声纹时，
同一个人的另一句话只有 **0.751**——录完就被自己拒之门外，这是 0.1.15 修掉的头号问题。
换成多句录入（录 10 秒、VAD 按句切、取均值）后，真机实测：

| 指标 | 真麦克风（CAM++，MacBook Pro 麦克风） | 合成语料（`say` 6 音色） |
| :--- | :--- | :--- |
| 同人最低 | 0.786（均值 0.79） | 0.8487 |
| 异人最高 | 0.715 | 0.7816 |
| 可用分界 | ≈ 0.75 | 0.80 ~ 0.84 |

**两个语料的最优阈值不重合，这是通道差异，不是一个能调参解决的问题**：
合成语音干净、电平满、无混响，同人与异人的相似度都被整体抬高；
真麦克风增益低（`voxos doctor` 实测峰值 0.0126，约 -38 dBFS）、有房间混响，
同一个人的两句话就掉到 0.79。一个标量阈值不可能同时落在两个区间的中点。

所以取舍是：**保人不保数**——宁可 FAR 1.67%（60 次冒充放过 1 次），也不能让主人被自己拒之门外。
这一项因此标 **GAP（标定边界）** 而不是 FAIL，判据是可测的：扫描表里**存在**
FRR = FAR = 0 的点，说明后端分得开，差的只是「一个阈值服务两种通道」。
它仍然被打印成 WARN，仍然算进「未达标」，不藏进 SKIP。

> 真修法是按通道标定：录声纹时一并记下通道（设备 + 电平），或者做 cohort 归一化
> （用一组背景说话人把分数 z-normalize）。两者都要改声纹档案格式，见
> `TODO_ROADMAP.md`「声纹阈值按通道标定」。到期日 2027-03-31 之前必须重新判断一次。

分布数据（合成语料）：同人相似度 `min 0.8487 / mean 0.9065`，异人相似度 `max 0.7816 / mean 0.4433`。

## 3. 全链路实测（真实语音 → 真实工具 → 真实文件）

```
语料: tts   声纹后端: sherpa-cam++   阈值: 0.82   录入一致性: 0.9651

#  声纹    音频      路由    转写 / 结果
1  0.95   6048ms   fast    Siri，我要写日志，今天把登录接口的空值校验补上了
   ↳ 日志已记录（DEV）  (1.7ms)
2  拒绝    4288ms   —       声纹不匹配，已丢弃            ← 冒充者，未进入 STT/LLM
3  0.94   5792ms   fast    Siri，检查一下服务器现在的负载和磁盘使用情况
   ↳ 负载 9.5/8.6，磁盘 95%，容器 0 个在跑  (126.6ms)   ← 真实系统指标
```

- 处理耗时 **446ms** 处理 **18.1s** 音频 → 实时率 **0.025×**（约为实时的 1/40）。
- 两条指令的派发延迟：**0.43ms**（写日志，纯本地文件）与 **203ms**（巡检，含 `docker ps` 子进程 3s 超时内的实际耗时）。
- 被拒的那条**没有消耗 STT 与 LLM**：声纹门禁在转写之前，这是"省电 + 省费 + 防误触发"的关键顺序。

## 7. 复现方式

```bash
cd voxos
make setup                         # 首次：建 .venv 并装依赖（约 20s）
python scripts/fetch_models.py     # 首次：CAM++ 与 Silero（约 28MB，必需）
                                   #       默认含 SenseVoice（229MB，可选）；--no-asr 只取声纹与 VAD
make test                          # 276 passed
make install-smoke                 # 构建 wheel 并装进临时 venv，验 6 项（源码跑看不到）
make verify                        # 回归模式：17 通过 + 2 项 GAP
make verify-release                # 发布门禁：GAP / SKIP 也算不通过
make demo                          # 真实语音端到端（沙箱写盘）
