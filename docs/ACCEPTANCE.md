**关于第 2 项：同一个 commit，同一台机器，两个数字。**
在文件 I/O 被沙箱代理的环境里这一项是 **23.4ms**，在无代理的 shell 里是 **0.371ms**——差 63 倍，
代码一个字没改。原因是「写日志」要落两个文件（日志 + 审计），而代理环境下单次 `write_text`
就要 **10.2ms**、`mkdir` 4.6ms。同一轮里纯路由决策 **0.0008ms**、上下文注入 **0.005ms**，
这两项不受 I/O 影响，两次几乎一致——正好交叉印证了差异出在文件系统，不在路由。
表中记的是无代理的数字；如果你的环境有类似的文件系统钩子，预期落在两者之间。

## 2. 声纹阈值标定（这不是拍脑袋的数字）

**语料**：macOS `say` 合成 6 个真实音色 × 4 句（Tingting 中文女声作主人；
Meijia 中文女声、Samantha / Karen / Moira 英文女声、Daniel 英文男声作冒充者）。
每音色前 2 句录入、后 2 句测试。**异人试验 60 次，其中含同性别中文女声（最难的冒充样本）。**

| 阈值 | FRR | FAR | 说明 |
| ---: | ---: | ---: | :--- |
| 0.70 | 0% | 13.33% | 太松，8 次里放过 1 次冒名 |
| 0.76（原规划值） | 0% | 1.67% | 仍不满足 FAR < 1% |
| 0.80 | 0% | 0% | 可用 |
| **0.82（当前配置）** | **0%** | **0%** | 同人最小 0.8487 / 异人最大 0.7816 的中点，两侧余量各约 0.03 |
| 0.84 | 0% | 0% | 可用，但同人侧余量只剩 0.009 |
| 0.86 | 8.33% | 0% | 开始误拒本人 |
| 0.90 | 50% | 0% | 一半的本人语音被拒 |

**决策**：采用 **0.82** 而不是规划文档里的 0.76。
0.76 在本语料上 FAR = 1.67%（10 次冒充放过 1.67 次），不满足 PRD 的 `< 1%`；
0.82 恰好落在实测分离区间 `[0.782, 0.849]` 的中点，两侧余量对称，
且 0.86 才开始出现 FRR，说明 0.82 还有 0.04 的噪声余量。

分布数据：同人相似度 `min 0.8487 / mean 0.9065`，异人相似度 `max 0.7816 / mean 0.4433`。

## 3. 全链路实测（真实语音 → 真实工具 → 真实文件）

```
语料: tts   声纹后端: sherpa-cam++   阈值: 0.82   录入一致性: 0.9651

#  声纹    音频      路由    转写 / 结果
1  0.95   6048ms   fast    Siri，我要写日志，今天把登录接口的空值校验补上了
   ↳ 日志已记录（DEV）  (1.7ms)
2  拒绝    4288ms   —       声纹不匹配，已丢弃            ← 冒充者，未进入 STT/LLM
3  0.94   5792ms   fast    Siri，检查一下服务器现在的负载和磁盘使用情况
   ↳ 负载 9.5/8.6，磁盘 95%，容器 0 个在跑  (126.6ms)   ← 真实系统指标
```

- 处理耗时 **446ms** 处理 **18.1s** 音频 → 实时率 **0.025×**（约为实时的 1/40）。
- 两条指令的派发延迟：**0.43ms**（写日志，纯本地文件）与 **203ms**（巡检，含 `docker ps` 子进程 3s 超时内的实际耗时）。
- 被拒的那条**没有消耗 STT 与 LLM**：声纹门禁在转写之前，这是"省电 + 省费 + 防误触发"的关键顺序。

## 6. 已验证 vs 未验证（诚实清单）

**已实测**
- 声纹 FRR/FAR（CAM++，6 音色 72 次试验）
- 快通道与派发延迟（2000 + 30 次采样）
- 全链路：真实 WAV → Silero VAD → 端点 → 声纹 → STT(脚本化) → 快通道 → 工具 → 落盘 → 审计
- 全链路：真实 WAV → SenseVoice-Small int8 真实转写 → 路由 → 工具（字符错误率 2.8%，36× 实时）
- 安全矩阵 12 个场景、角色隔离、确认闸门
- UI：状态总线、SSE、`/state`、`/command`、Earcon 合成、胶囊 HTML 结构
- UI 视觉：`scripts/shot.py` 驱动真实页面截 10 个状态，并用 `getBoundingClientRect` 当探针
- Silero VAD 真实推理：真实语音检出率 92%，静音误报 0%，算力 3.9ms / 秒音频

**未验证（不要当成已实现）**
| 项 | 为什么没测 | 风险 |
| :--- | :--- | :--- |
| 真人声纹标定 | 无真人录音样本 | TTS 音色的类内方差小于真人，真人 FRR 可能更高 |
| 中英混说术语识别 | 语料里的英文是中文音色读的，词级错误率 12.5% | 代码术语必须靠热词注入补，声学模型自己扛不住 |
| 真麦克风 8 小时长稳 | 需要授权与长时间占用设备 | CPU/内存长稳、蓝牙热插拔的真实行为未测 |
| 面罩/低语模式 | 无硬件 | `mask_mode` 的 EQ/AGC 只做了信号级单测 |
| LLM 慢通道 | 未接真实模型（无 Key） | 多轮 tool_calls 只在代码路径与错误兜底上测过 |
| 拖拽 / 长按 / 动效逐帧 | 只覆盖静态与 hover/焦点状态 | 交互时序上的视觉问题看不出来 |

## 7. 复现方式

```bash
cd voxos
make setup                         # 首次：建 .venv 并装依赖（约 20s）
python scripts/fetch_models.py     # 首次：CAM++ 与 Silero（约 28MB，必需）
                                   #       加 --all 连 SenseVoice（229MB，可选，缺了就退回 scripted）
make test                          # 157 passed
make verify                        # 18/18，产出 docs/acceptance.json + ACCEPTANCE.html
make demo                          # 真实语音端到端（沙箱写盘）
```

**全新克隆实测**：把 `.voxos/models/` 整个挪走后再跑（等价于刚 clone 下来、还没下模型），
得到 `154 passed, 3 skipped` —— 跳过的是 Silero VAD 1 项 + SenseVoice 2 项（缺模型文件时按设计
skip，而不是假装通过）。这条验证的是"提交里没有漏文件"，不是"功能没问题"。
```

`make verify` 会在 `.voxos/verify/` 沙箱内运行，**不会写入你的真实日志目录**。
