# 可观测性与自增强

> 这份文档回答一个问题：**「我发了很多指令，但没用」——去哪查？**
>
> 结论先放这里：在 0.1.31 之前，这个问题的答案**不存在于任何日志里**。
> 不是日志不够多，是少了「一次对话回合」这个单位。

## 1. 那次「没用」到底发生了什么

真机复现（0.1.31 之前）：

```
用户说：请打开微信
胶囊：聆听中 + 字幕「请打开微信。」     ← 识别成功了
然后：什么都没有。status.jsonl 最后一条是 6 分钟前的「待机」
```

查不到的原因有两层，叠在一起：

**第一层：声纹只录了 1 个样本。** `~/.voxos/voiceprint_profiles.npz` 里只有
一个 192 维向量。配置注释自己写着「只录 1 句时同人换句话只有 0.751」，而阈值
默认 0.75——**差 0.001**。于是同一句话这次过、下次不过，而用户看到的只有
「已录入」三个字。

**第二层：被拒时完全静默。** `main.py` 的派发循环里是一句裸的：

```python
if not utterance.accepted:
    continue          # 原因（Utterance.reason）就在这里被扔掉了
```

而 `_drop` 返回的是**空字符串**，连「我听到的是哪句」都没留下。所以音频层
丢掉的东西，上面两层永远不知道。

## 2. 三层记录，各管一件事

| 层 | 文件 | 单位 | 回答什么问题 |
| :--- | :--- | :--- | :--- |
| 状态 | `~/.voxos/status.jsonl` | 一次状态变化 | 「现在在干什么」（待机/聆听/处理中/完成） |
| **时间线** | `~/.voxos/timeline.jsonl` | **一次对话回合** | 「刚才那句话怎么了」 |
| 审计 | `~/.voxos/audit.jsonl` | 一次工具调用 | 「那个命令的参数和结果是什么」 |

三层不能合并，因为它们的粒度不同：一句话可能触发零次工具调用（`dropped` /
`missed`），也可能触发三次（LLM 多轮）。用工具调用当单位，就永远记不下
「没调工具的那些」。

## 3. 时间线的四种结局

`timeline.Turn.outcome` 只有五个值，每个对应一种「用户感知」：

| outcome | 含义 | 用户看到什么 | 该修什么 |
| :--- | :--- | :--- | :--- |
| `dropped` | 音频层就丢了 | 现在：**什么都没有** | 声纹 / 麦克风 / 阈值 |
| `missed` | 进了派发，没匹配上 | 「没听懂」 | 快通道正则的盲区 |
| `acted` | 调了工具，成功 | 「完成」+ 结果 | 没事 |
| `failed` | 调了工具，报错 | 「失败」+ 原因 | 工具或环境 |
| `chatting` | 闲聊 / LLM 回话 | 「回话」 | 没事 |

**`dropped` 这一行是重点**：它以前完全不存在。区分 `dropped` 和 `missed`
尤其重要——前者是「没听见」，后者是「听见了但不懂」，修的地方完全不同。

### 一条记录里有什么

```json
{
  "ts": "2026-10-29T13:45:02", "outcome": "dropped",
  "text": "请打开微信",          // 用户说的（丢弃时是已经识别出来的半句）
  "score": 0.74,                 // 声纹相似度 ← 0.74 < 0.75，答案就在这里
  "audio_ms": 1400,              // 这句有多长
  "route": "", "tool": "", "args": {},
  "ok": true, "reply": "",
  "reason": "声纹不匹配，已丢弃",   // 为什么没做
  "ms": 0
}
```

`acted` 的回合还会带 `tool` / `args` / `ms`，所以「它到底跑了什么命令」
在一条记录里就能看完，不用去审计里对时间戳。

## 4. 抗体库：把犯过的错变成能查的东西

`src/voxos/lessons.py` 做三件事，对应三种经验：

### 4.1 症状 → 修法（静态知识）

```python
SYMPTOMS = {
    "声纹不匹配": ("档案和麦克风对不上，或只录了 1 句",
                   "voxos enroll --record 3   # 录 3 句取均值"),
    "太短":      ("人声没到 min_speech_ms，被当咳嗽放过去了", "..."),
    "空转写":    ("识别没出字：麦克风静音、增益太低", "..."),
    ...
}
```

**修法必须是能直接粘进终端的一句话。**「请检查配置」等于没说，用户不知道
检查哪一项。

### 4.2 从时间线数（不是猜）

`diagnose(turns)` 统计最近 N 个回合里哪类失败最多，排前三。用户打开面板
第一眼看到的就是**当前最该修的那件**，而不是一份固定清单。

### 4.3 没听懂的话术（唯一能自动发现盲区的入口）

`unmatched(turns)` 收集 `missed` 的句子，去重后按出现次数排：

```
没听懂的话（攒够几条就该加一条快通道正则）：
  · 把那个东西弄一下（2×）
  · 嗯
```

这是「自增强」最实在的一条：**系统不需要变聪明，只需要把盲区攒起来给人看。**
攒够十条，加一条正则，永久解决。单句看不出来，十句放在一起就是需求。

## 5. 怎么用

```bash
voxos log                  # 最近 30 个回合 + 最该修的三件事 + 没听懂的话
voxos log --limit 100      # 往前翻
voxos doctor               # 声纹样本数、字幕、判停、设备峰值
```

胶囊的「最近」页读的是同一个文件（`/api/history` → `timeline.recent`），
所以终端和界面看到的永远一致。

## 6. 已知不足（诚实清单）

| 不足 | 影响 | 下一步 |
| :--- | :--- | :--- |
| 时间线没有轮转 | 长期开着会一直长（每回合约 300 字节，一年约 10MB，可接受但不优雅） | 按大小切分 + 保留最近 N 天 |
| `risk` 字段还是空的 | 时间线里看不到风险等级，要去审计里查 | 从 `safety` 补 |
| 没有跨回合关联 | 「同一句话说三次都没懂」要看 `unmatched` 的计数，不是自动合并 | 按文本聚类 |
| 抗体库是静态表 | 新增的失败类型不会自己长出修法 | 从 `reason` 里挖高频词，提示「这一类还没写修法」 |
| 没有回放 | 想复现「那次为什么没听懂」需要原始音频，我们只存文本 | 可选：保留失败回合的 3 秒音频（要注意隐私） |

## 7. 一条原则

**静默的失败比失败本身更贵。**

用户能接受「没听懂」，不能接受「不知道有没有听懂」。所以这个项目的默认
不是「少报错」，而是「每一次没做到都要留一条能查到的记录」——
哪怕它看起来像噪音。噪音可以调阈值，空白只能靠猜。
