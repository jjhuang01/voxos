# 产品与工程审查（REVIEW）

> 审查时间：2026-10-27｜方法：**抽查，不通读**。真起服务、真发跨站请求、真测延迟、真改配置，
> 不看"文档说它应该怎样"。结论分三类：已修 / 未修（附风险）/ 不打算修（附理由）。

## 1. 一句话结论

功能闭环是通的，但**产品的"入口"和"第一次使用"是断的**：一个陌生页面能直接命令它干活，
而一个真人第一次装上它，只会看到一句"先运行 voxos enroll"然后进程退出。这轮把这两头补上了。

### 关于第 1 条，为什么它最严重

这个产品的全部卖点是"危险操作在架构上不可能发生"。红线网关把关的是**工具**，
但**入口**是裸的：任何本地页面（包括你正在浏览的任意网站）都能发一个 simple request 过来。
`fetch('http://127.0.0.1:8765/command', {method:'POST', body:'把 README 改成...'})`
—— 不需要 CORS 预检，因为 `text/plain` 属于简单请求；服务端也没校验 `Origin`。
**安全边界画在了门后面。**

现在的模型（`REDLINES.md §6`）：只有页面本身免令牌；其余全部要本次运行的随机令牌，
且拒绝非本机同源的 `Origin`。令牌在服务端渲染页面时注入，跨站页面读不到它（同源策略挡着）。

## 4. 设计取舍（为什么是现在这个样子）

**为什么不做主窗口。** 语音助手的价值是"不用看屏幕"。一旦有了主窗口，产品就会开始争夺注意力：
未读红点、历史列表、推荐操作 —— 这些是聊天机器人的形态，不是操作系统的形态。
张小龙讲的"用完即走"在这里的具体含义是：**你说话，它做事，胶囊闪一下，然后它消失。**

**为什么设置放在展开态而不是独立页面。** 设置是低频动作，但它必须"伸手可及"。
独立页面意味着用户要记住一个 URL 或找一个入口；展开态意味着"它就在那儿"。
代价是信息密度受限，所以只放 19 个真正会改的字段，其余留在 TOML 里给愿意读文件的人。

**为什么保留"最近 8 条"。** 语音产品最大的信任缺口是"我明明说了"。
不给回看，用户就无法判断是麦克风、声纹、识别还是路由的问题。这一条不是功能，是排错基础设施。

**为什么危险字段标「重启生效」。** 端口、识别后端、面罩模式改了要重建管道。
假装能热更，只会让用户以为改坏了。**说清楚比做得漂亮重要。**

## 6. 这一轮新增的验收项

从 10 项扩到 **14 项**，新增的四项都是"抽查出来的坑"，不是凑数：

1. **跨站 / 无令牌请求被拦截** —— 401 / 403 / 200 三个码都要对，且被拒的请求**一次都不能执行**。

3. **设置写回保住注释** —— 改值、保注释、写到 `--config` 指定的文件、非法值一个字节都不写。
4. **无声纹时给出录入入口** —— 不再是"打印一行然后退出"。

# 第四轮：把「没做」逐条做掉（2026-10-28 凌晨）

## 15. 真实 STT 接上了，也量出了它到底行不行

SenseVoice-Small int8（sherpa-onnx，229MB）接进 `audio.py`，设置页切
`stt.backend = sense_voice` 即用，缺模型时退回 `scripted` 而不是崩。

实测：24 句 TTS 语料 / 818 字符 / 6 个音色。

| 指标 | 实测 |
| :--- | :--- |
| 字符错误率（总体） | **2.8%** |
| 中文 | 1.4%（8 句 142 字，只有 1 句有差异） |
| 英文 | 3.1%（16 句，按字符算） |
| 实时率 | **33–38× 实时**（2.1–2.4s 处理 79s 音频，单次有抖动） |

两件必须说清楚的事：

1. **中文那 1.4% 不是错。** 唯一有差异的是「明天上午十点」→「明天上午10点」——SenseVoice 的
   withitn 逆文本规范化在把中文数字转阿拉伯数字。按字面算错 2 个字符，按语义算是 0 个。
   中文的真实错误率是 **0**。
2. **英文 3.1% 是字符级，会骗人。** 按词算是 **12.5%（21/168）**：`null` → `Ill` / `and I'll`、
   `auth` → `Oth` / `o` / `author`、`dev` → `Dave`、`login timeout` → `log and time' out`。
   原因是语料里的英文是中文音色读的——声学上本来就是中式英语，模型把 `auth` 听成 `author` 反而合理。
   **这恰好证明热词注入（Task 2.3）不是可选项**：代码术语必须走热词表，不能指望声学模型自己扛。

顺带把 `fetch_models.py` 改成「ASR 模型缺失只警告不失败」——它是可选的，缺了就退回 `scripted`。

## 16. 派发延迟差 63 倍，查下来是环境

这一轮验收先跑出端到端 p95 = **23.4ms**，而上一轮记录的是 0.90ms。差 26 倍，必须查。

查下来是环境，不是代码：那次运行的 `open()` 被沙箱代理到宿主进程（`sitecustomize.py`
的 `_brokered_open`），单次 `write_text` 要 **10.2ms**、`mkdir` 4.6ms。而「写日志」这条链路
要写两个文件（日志 + 审计），17ms 正好对上。

后来同一条命令换到没有代理的 shell 里再跑，同一项变成 **0.371ms**。**63 倍，代码一个字没改。**

| 环节 | 沙箱代理 I/O | 无代理 |
| :--- | ---: | ---: |
| 快通道路由决策 | 0.0008ms | 0.0008ms |
| 上下文注入 | 0.007ms | 0.005ms |
| 端到端（含两次落盘） | 23.4ms | **0.371ms** |
| 一次 `write_text` | 10.2ms | — |

关键不是哪个数好看，而是**前两项两次几乎一样**——它们不碰文件系统。差异只出现在落盘那一段，
这才能把结论钉死在"文件 I/O"上，而不是"机器当时有点忙"。

## 17. 这一轮自己审出来的四个问题

## 18. 截图工具的第三课：headless Chrome 不产帧

给撤销按钮量宽度时撞上一个鬼故事：`.btn.sec` 规则明明命中（`matches()` 返回 true、
`cssRules` 里也翻得到），`getComputedStyle` 却死活返回旧值——连注入
`#reset{flex:0 0 auto !important}` 都压不住，我一度以为撞上了浏览器 bug。

真相是 CSS `transition: .15s`。headless Chrome 不主动产帧，动画时钟不走，过渡永远停在起始值；
`getComputedStyle` 和 `getBoundingClientRect` 读到的都是**改之前**的样子。逼出一帧
（随便截一张图）之后，三个按钮立刻回到 84 / 84 / 174。

修法：`shot.py` 加 `settle()`，截图前先用两张 quality=1 的 jpeg 把动画时钟推过去。

同一个坑还咬了第二口：`.stage:has(.confirm:not([hidden])) .panel{max-height:calc(100vh-200px)}`
这条规则（确认卡出现时把面板压矮，好让卡片留在窗口里）在 `getComputedStyle` 里读到的永远是
`550px`（未压缩的值），要逼出一帧才变成 `420px`。**也就是说，在真机上它是好的，在截图里它是坏的**——
如果我只信截图，就会去改一条根本没问题的规则。

上一轮的教训是「截图会骗人，量出来的数不会」。这一轮得补两句：
**量出来的数也会骗人，如果渲染管线没走完**；而且**"逼一帧"必须成为测量前的固定动作**，
不然同一个坑会用不同的样子反复出现。

## 19. 设置撤销：只退一步，退完就没了

`settings.bak` 存在配置文件旁边的 `.voxos/` 里（跟着 `--config` 走，不污染仓库根）。
保存前留一份，撤销时写回去，然后把备份删掉。

- 只退一步是刻意的：配置不是代码，多级撤销没人用，还会让"现在到底是什么状态"变模糊。
- 退完按钮就消失（`/api/settings` 带 `undo` 字段），不留一个点了没反应的灰按钮。
- 备份写成功才删，写失败备份还在——撤销失败不该把退路也弄丢。

端到端验过：`0.82` → 保存 `0.90` → 备份里是 `0.82` → 撤销 → `0.82` → 备份没了 →
再撤销返回 409「没有可撤销的保存记录」。
