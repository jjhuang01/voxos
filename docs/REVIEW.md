# 产品与工程审查（REVIEW）

> 审查时间：2026-10-27｜方法：**抽查，不通读**。真起服务、真发跨站请求、真测延迟、真改配置，
> 不看"文档说它应该怎样"。结论分三类：已修 / 未修（附风险）/ 不打算修（附理由）。

## 1. 一句话结论

功能闭环是通的，但**产品的"入口"和"第一次使用"是断的**：一个陌生页面能直接命令它干活，
而一个真人第一次装上它，只会看到一句"先运行 voxos enroll"然后进程退出。这轮把这两头补上了。

## 2. 发现的问题（按严重度）

| # | 级别 | 问题 | 证据 | 状态 |
| :-- | :-- | :--- | :--- | :--- |
| 1 | **P0** | 任意网页可 POST `/command` 驱动 Agent 执行工具 | 带 `Origin: https://evil.example` 的请求返回 **200 且真的执行了** | 已修：令牌 + 同源校验 |

### 关于第 1 条，为什么它最严重

这个产品的全部卖点是"危险操作在架构上不可能发生"。红线网关把关的是**工具**，
但**入口**是裸的：任何本地页面（包括你正在浏览的任意网站）都能发一个 simple request 过来。
`fetch('http://127.0.0.1:8765/command', {method:'POST', body:'把 README 改成...'})`
—— 不需要 CORS 预检，因为 `text/plain` 属于简单请求；服务端也没校验 `Origin`。
**安全边界画在了门后面。**

现在的模型（`REDLINES.md §6`）：只有页面本身免令牌；其余全部要本次运行的随机令牌，
且拒绝非本机同源的 `Origin`。令牌在服务端渲染页面时注入，跨站页面读不到它（同源策略挡着）。

## 3. 用户旅程审查

| 场景 | 之前 | 现在 | 还缺 |
| :--- | :--- | :--- | :--- |
| 第一次安装 | `make setup` → `doctor` → `demo` 能跑；但 `run` 直接退出 | `run` 进入 ONBOARD，面板弹出「录入声纹」，录 3 秒即进入待机 | 没有安装包/开机自启脚本 |
| 日常使用 | 说一句话 → 胶囊闪一下 → 结果只在终端 | 胶囊 + 面板 + 最近记录 + 语音播报 | 无打断词（说"停"不能中止播报） |
| 它听错了 | 无从查证 | 「最近」里能看原文与结果 | 不能一键"重说"或纠正 |
| 危险操作 | 终端里等 `y`，GUI 用户完全不知道该干嘛 | 面板下方出现确认卡，允许/拒绝；超时按拒绝 | 无"记住这个选择" |
| 改配置 | 改 TOML + 重启 | 面板内改，保存即生效；被环境变量接管的字段置灰 | 无配置历史/撤销 |
| 出错 | 只在终端 | 胶囊变红 + 面板提示 + 状态卡 | 没有"一键诊断"按钮 |

## 4. 设计取舍（为什么是现在这个样子）

**为什么不做主窗口。** 语音助手的价值是"不用看屏幕"。一旦有了主窗口，产品就会开始争夺注意力：
未读红点、历史列表、推荐操作 —— 这些是聊天机器人的形态，不是操作系统的形态。
张小龙讲的"用完即走"在这里的具体含义是：**你说话，它做事，胶囊闪一下，然后它消失。**

**为什么设置放在展开态而不是独立页面。** 设置是低频动作，但它必须"伸手可及"。
独立页面意味着用户要记住一个 URL 或找一个入口；展开态意味着"它就在那儿"。
代价是信息密度受限，所以只放 19 个真正会改的字段，其余留在 TOML 里给愿意读文件的人。

**为什么保留"最近 8 条"。** 语音产品最大的信任缺口是"我明明说了"。
不给回看，用户就无法判断是麦克风、声纹、识别还是路由的问题。这一条不是功能，是排错基础设施。

**为什么危险字段标「重启生效」。** 端口、识别后端、面罩模式改了要重建管道。
假装能热更，只会让用户以为改坏了。**说清楚比做得漂亮重要。**

## 5. 仍然没修 / 不打算修

| 项 | 为什么 | 风险 |
| :--- | :--- | :--- |
| 真实 STT 识别率 | 未接 SenseVoice / Whisper 权重 | 真实场景准确率未知 |
| 真麦克风 8 小时长稳 | 需要长时间占用设备 | CPU/内存长稳未测 |
| 真人录音声纹 | 无真人样本，只有 TTS 语料 | 真人 FRR 可能高于 0% |
| 像素级视觉走查 | 本机无头浏览器被沙箱拦截，只做了 DOM 结构与 id 引用校验 | 可能存在布局细节问题 |
| 开机自启 | 需要 launchd plist，属于安装器范畴 | 用户要手动起 |
| 多用户 / 多声纹 | 产品定位是"只听主人" | 家庭成员无法共用 |

## 6. 这一轮新增的验收项

从 10 项扩到 **14 项**，新增的四项都是"抽查出来的坑"，不是凑数：

1. **跨站 / 无令牌请求被拦截** —— 401 / 403 / 200 三个码都要对，且被拒的请求**一次都不能执行**。
2. **上下文注入不阻塞派发** —— p95 < 5ms（修复前是 271ms）。
3. **设置写回保住注释** —— 改值、保注释、写到 `--config` 指定的文件、非法值一个字节都不写。
4. **无声纹时给出录入入口** —— 不再是"打印一行然后退出"。

## 7. 审查方法留档（下次照做）

```bash
# 1. 跨站能不能驱动？（修复前应看到 200）

# 2. 热路径到底多慢？（不要信 verify 的数字，要信真实调用链）
PYTHONPATH=src python -c "import time; from voxos import main; \
t=time.perf_counter(); [main._context() for _ in range(5)]; print((time.perf_counter()-t)/5*1000)"

# 3. 没有声纹时会发生什么？（把 profiles 指到一个不存在的文件再 run）
# 4. 设置页到底写到哪个文件？（用 --config 指到 /tmp 再点保存，然后 diff）
```

**教训**：验收脚本测的必须是**产品真正走的那条路径**。测了一条更快的旁路，
得到的不是"性能好"，是"不知道性能"。

# 第二轮：原子级审查（2026-10-27 晚）

这一轮不再看"功能有没有"，而是**逐条链路走到底**：一句自然语言 → 路由 → 工具 → 落盘；
一次喊停 → 回声门 → 端点 → 转写 → 停播报。凡是断的，都算 bug。

## 8. 打通了像素级走查

之前说"截不了图"是错的。真因不是沙箱，是**页面里的 SSE 长连接让 Chrome 的 load 事件永不结束**，
`--screenshot` 就一直等，最后被超时杀掉。给页面加了个 `?still=1`（不连 SSE，供截图与文档用），
Chrome 立刻就能出图。

看到图之后改的东西：次要文字对比度（`#6E747E` 在深底上只有 3.4:1，不到 AA）、
滑块与数字框不对齐、单位贴边、面板 392→400、关闭按钮字号、状态值加语义色（已录入=绿、演练=琥珀）。
